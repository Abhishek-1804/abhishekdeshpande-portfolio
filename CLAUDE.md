# CLAUDE.md

Guidance for Claude Code (or any model) working in this repository. Read `HANDOFF.md` too: it says what is finished, what is in progress, and what to do next.

## What this is

Abhishek Deshpande's portfolio at https://abhishekdp.com (note the spelling: abhishe**k**dp). It is an interactive 3D site built with three.js and Vite, plus a static Markdown blog, deployed to GitHub Pages by GitHub Actions.

History, so old names in git make sense:
1. Hugo + PaperMod (original).
2. "Flight Log": fly a plane between islands (live for two days in Nov 2026; replaced by Skyline).
3. **"Skyline"** (live on `main` since 2026-11-11; also on branch `skyline-swing`): a New-York-style city at sunset. The visitor clicks a section and an original masked hero swings through the streets on a grapple line to that section's tower, lands on the roof, and the section's info opens.

## Hard constraints from the owner

- **No Spider-Man / Marvel / Insomniac assets or likeness.** The owner asked for a "Spider-Man theme"; the hero must stay an original character (no red-and-blue web suit, no spider emblem, no teardrop eye lenses, no "web" branding, no recreation of that game's map or look). A New-York-inspired city is fine because it is a real place. Make the hero *move* like a web-swinger; do not make them *be* one.
- **Everything is procedural.** No downloaded 3D models, textures or audio. Geometry, shaders, canvas textures and Web Audio only.
- **Do not open a visible external browser to test.** The in-app browser pane has no WebGL (the site falls back to the classic view there). Test the 3D with the headless driver below.
- **Must look decent on phones.**
- **Autopilot first, controls optional.** Section buttons that send the hero on autopilot are the main navigation. Manual control is light: drift, boost, free roam.
- **Never push to `main` without the owner saying so.** Pushing `main` deploys to the live site.
- Content edits are the owner's job later; keep all text in `src/content.js`.

## Commands

```bash
npm run dev       # Vite dev server (3D site only; blog pages are generated by build)
npm test          # physics + routing test suite (node --test, no browser needed)
npm run build     # vite build && node scripts/build-blog.mjs  ->  dist/
npm run preview   # serve dist/ on :4173

# Look at the 3D without a window (needs the preview server running):
node scripts/dev/shot.mjs scripts/dev/steps-example.mjs            # desktop 1440x860
node scripts/dev/shot.mjs scripts/dev/steps-phone.mjs 390 844 m    # phone
# Other step files: steps-trip.mjs (each phase of a trip), steps-times.mjs (night/midday),
# steps-roam.mjs (free roam, re-target, Skip, quality fallback).
# Screenshots land in scripts/dev/shots/*.jpg (git-ignored). Read them with the Read tool.
```

`?debug` on the URL exposes `window.__city = { scene, camera, renderer, env, city, hero, orbs }`. Set `__city.freecam = { pos: [x,y,z], look: [x,y,z] }` to park the camera anywhere (set it to `null` to give it back to the hero).

Software WebGL in the headless browser runs at a few frames per second, and the sim clamps `dt` to 1/20 s, so in-page time runs slow. In steps files, poll hero state (`hero.state.mode`, `hero.traversal.mode`) instead of sleeping fixed times.

### The city grid (`src/sim/layout.js`)

- 13 x 13 blocks. `BLOCK = 84` m, `STREET = 28` m, `PITCH = 112` m, `HALF = 728` m. Street line `k` (0..13) is at `k * PITCH - HALF`; block `i` lies between lines `i` and `i+1`.
- The hero only uses the core streets, lines 2..11 (`CORE_LINES`). Outer rings are skyline filler.
- `SITE_BLOCKS` places one tower per section plus `home`. Every tower is 56 m square in an otherwise empty block (a plaza), approached from its **west** street: `site.access` (street point), `site.edge` (roof edge), `site.perch` (where the hero stands), `site.out = {x:-1, z:0}`.
- `PARK_BLOCKS` is a 1 x 3 strip with no buildings. Street stretches with park on both sides have nothing to hang a rope from, so the planner treats them as closed (`openStretch`).
- `generateLayout()` returns `buildings` (boxes incl. setback tiers, each with `style` 0 brick / 1 stone / 2 glass / 3 modern), `spires`, `waterTowers`, `roofBoxes`, `sites`, `heightAt(x,z)` (any solid) and `roofAt(x,z)` (base footprint only; used for rope anchors).
- `planRoute(from, to, heading?)`: Dijkstra over (intersection, arrival direction). Routes follow street centre lines, never U-turn, never reverse the current heading. `roamTarget()` picks the next block for free roam. `roomAhead()` is the distance to the next intersection.

### Swing physics (`src/sim/traverse.js`)

The key idea: the hero is constrained to a route. State is `s` (metres along the route), `y` (height), `vs`, `vy`, and `lat` (sideways drift, player-controlled, max 9 m). The rope constraint is solved in the (s, y) plane. That is why the hero can never enter a building: the path is always over a street, whatever the frame rate.

- `air`: gravity; when falling and below `TUNING.ceiling`, `findAnchor()` looks for a real building face ahead (alternating sides) and attaches.
- `swing`: gravity + rope-length constraint + a push toward cruise/boost speed; reels in if the arc would dip below `minHeight`; releases ~0.8 rad past vertical.
- `done` is true `TUNING.arrive` metres before the route's end; `hero.js` then plays the landing.
- `launchCurve()` / `zipCurve()` are the Bezier paths off and onto rooftops. `HANDOFF` is the state where the launch dive hands over to the physics.
- `retarget()` re-plans mid-swing (waits until there is 36 m of straight road so turns stay smooth). `extendRoam()` keeps free roam going one block at a time.

**If you change the layout or tuning, run `npm test`.** The suite simulates all 72 tower-to-tower trips at 144/60/30/20 fps and asserts: always arrives, never inside a building footprint, never below the street, rope never stretches, every rope end is on a real wall (zero "virtual" anchors), launch/landing curves clear all buildings, mid-swing re-routing does not teleport, and two minutes of free roam from every tower stays in bounds.

### Hero (`src/world/hero.js`)

State machine in `s.mode`: `idle` (on a roof) -> `launch` (Bezier dive) -> `travel` (Traversal physics) -> `zip` (Bezier pull up to the roof) -> `land` (crouch) -> `idle`.

- `goTo(site, onArrive)` autopilot; works mid-trip (sets `pending`, applied by `retarget`).
- `roam()` free roam; `skip()` jumps straight to the destination.
- `view(outPos, outLook, t, portrait)` says where the camera wants to be; `main.js` smooths it.
- Emits `launch`, `attach`, `release`, `land`, `reroute` (used for sound and UI).
- Rig: `buildRig()` builds joints from primitives; `POSES` are joint angles; `swingPose()` is procedural. The character faces +Z and its left is +X.

### Rendering notes (`src/world/city.js`)

- All buildings are one `InstancedMesh` with a custom `ShaderMaterial`. Per-instance attributes: `aSeed`, `aStyle`, `aTint`, `aHue` (non-zero for section towers: glowing corners and crown). The fragment shader draws windows, piers, sills, cornices, storefronts, blinds, lit rooms and sky reflections procedurally, with a distance fade (`lod`) so far windows do not shimmer.
- Custom shaders do not get three.js lights or fog automatically. `city.update()` copies sun, ambient, horizon/zenith and fog from `env.state` into shared uniforms every frame. If you add a time-of-day field, add it to `numeric` or `colors` in `environment.js`.
- There are no shadow maps. Shadow is faked: `uShade` (how low the sun is) darkens facades near the street and everything on the ground except the east-west streets, which the low sun shines straight down.
- Use the sine-free `hash()` in `GLSL_COMMON`, and `flat varying` for per-instance values; the usual `fract(sin())` hash sparkles on software GL.
- Colours above 1.0 bloom (threshold 1.0 in `main.js`). Keep emissive things modest.

### Classic view, SEO, no-WebGL

`vite.config.js` bakes `renderClassic()` into `index.html` at build time (search engines and no-JS visitors). If WebGL is missing or `boot()` throws, `main.js` shows that classic view. Keep this path working.

## Blog

Posts are `content/posts/*.md` (file name = URL slug). `scripts/build-blog.mjs` runs after `vite build` and writes post pages at `/posts/<slug>/`, the list, tag pages, RSS at `/index.xml` and `/posts/index.xml`, sitemap, robots, 404, and redirects for old Hugo URLs.

Frontmatter:
```yaml
---
title: "Post Title"
date: YYYY-MM-DDTHH:MM:SS-07:00
draft: false
tags: ["tag1", "tag2"]
---
```
No cover images. Drafts and future-dated posts are skipped. Hugo-style `{#custom-id}` headings work. Each post starts with ASCII art in a code block **with no language**; un-labelled blocks render as glowing centred art, labelled blocks get syntax highlighting and a copy button.
